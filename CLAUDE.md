# machine-learning-self-learning

## Context

Varun is learning Machine Learning as part of an enrolled course, alongside the parallel `python-self-learning`, `sql-self-learning`, and `statistics-self-learning` tracks in this same `2026` project folder. This is the track those three were building toward — Python for writing code, SQL for pulling/shaping data, and Statistics for the mathematical foundation ML sits on.

Chapter 1 ("Machine Learning Foundations") covers, in this order: why ML exists (vs. traditional rule-based programming) → the three types of ML (Supervised, Unsupervised, Reinforcement) and their sub-types (Classification/Regression, Clustering/Dimensionality Reduction) → a conceptual overview of each of the three learning types → Parametric vs. Non-Parametric models (a second, independent axis for categorizing algorithms — fixed-size distilled formula vs. grows-with-data) → a short end-of-chapter recap walking through a structured checklist for approaching a vague business problem (deliberately moved to the very end, Varun's request, so the concept-learning flow isn't interrupted mid-chapter). Written to `01-Machine Learning Foundations/theory.md`, with hands-on scenario-based practice problems in `types_of_ml_practice.ipynb` — Varun asked for these filled in with working code + explanations (not scaffold-only) since this is early learning phase, each cell showing the *shape* of that ML type's data (labeled data for supervised, unlabeled for unsupervised, agent/action/reward for RL) with meaning + expected-output comments per line, same convention as `python-self-learning`'s reference notebooks. Also clarifies two common confusion points: (1) classification targets are **categorical** (nominal/ordinal), not "discrete" in the stats sense — discrete is a numeric type under Regression; (2) a trained clustering model can be applied to new data (assigns it to the nearest existing cluster) but that's a similarity-based *assignment*, not verifiable "prediction" like supervised learning, since there's no ground-truth label to check against.

Chapter 2 ("Linear Regression") is the first full algorithm, going deep on theory + math only (Varun explicitly wants theory/math first, code later as a separate follow-up step). **Notation: uses plain `y = mx + b` throughout, not $\hat{y} = \beta_0 + \beta_1x$** — Varun found the beta/hat notation unreadable on first pass, so the chapter was rewritten around the school-algebra version (with a note up top translating to $w$/$\beta$ notation for when he sees it elsewhere) and closely follows the flow of a prior conversation that actually clicked for him. Covers: the `y=mx+b` formula on a clean worked house-price dataset, why messy real data breaks the "just pick 2 points" shortcut (worked numerically with 3 different point-pairs giving 3 different slopes), Mean Squared Error (MSE) as the cost function (not SSE) with a hand-worked comparison of two candidate lines, Ordinary Least Squares (OLS, direct solve) vs. Gradient Descent (iterative, with a verified one-step-by-hand walkthrough showing MSE dropping 67,885 → 15,380), using the trained model to predict, Multiple Linear Regression and the "formula shape never changes, only the learned numbers do" insight, Linear Regression's assumptions (linearity, independence, homoscedasticity, normality, no multicollinearity), and RMSE/R² as human-readable fit metrics. Written to `02-Linear Regression/theory.md`, all worked numbers verified with a script before writing. No code yet in this chapter — that comes as an explicit next step once the math is solid.

Chapter 3 ("Logistic Regression") is the second full algorithm, same theory+math-only style and plain `m`/`b`/`x`/`y` notation as Chapter 2. Covers: why Logistic Regression is classification despite the name (built on Linear Regression's machinery but predicts a category); why fitting a straight line to 0/1 data breaks (out-of-range outputs, wrong S-shape); the Sigmoid function (`p = 1/(1+e^-z)`, with `z = mx+b` computed exactly as in Chapter 2) squashing any `z` into a 0-1 probability, with a full worked exam pass/fail dataset (decision boundary lands exactly at the threshold); thresholding at 0.5 to get a category; why MSE doesn't work as the cost function here (doesn't punish confident-wrongness harshly enough) and Log Loss / Binary Cross-Entropy as the fix, with worked numbers showing confident-correct (loss 0.01) vs confident-wrong (loss 4.6) vs unsure (loss 0.69); why Logistic Regression has no direct-solve formula like OLS and must use Gradient Descent; a preview mention of Multinomial/Softmax Regression for 3+ categories; assumptions (linearity of log-odds, independence, no multicollinearity, sample size per class); and a short Odds/Log-Odds side-note tying back to the "linearity of log-odds" assumption. Written to `03-Logistic Regression/theory.md`, all worked numbers (sigmoid values, log loss) verified with a script before writing.

Both Chapter 2 and Chapter 3 have a `scripting.ipynb` — real, executed, code end-to-end data science workflows (not scaffold, not toy data), each structured around **Varun's course's 10-step ML pipeline diagram** (not the generic 7-step shape used earlier): Business Understanding → Data Collection → Data Understanding → Data Preparation → Model Building → Model Training → Model Testing → Model Evaluation → Model Deployment → CI/CD. "Model Deployment" concretely means saving the trained model to a `.pkl` file via `joblib` and proving a fresh process can load and predict with it, with a note that wiring it into a real UI/API is typically where DS work hands off to ML/Software Engineering. "CI/CD" is explained conceptually only (not runnable in a notebook) — ties to model drift and why retraining/reshipping needs automation over time.

- **`02-Linear Regression/scripting.ipynb`** — trains Linear Regression on `assets/Cars.csv` (81 rows: HP, MPG, VOL, SP, WT) to predict `MPG`, confirmed with Varun. Data Understanding step surfaces a real multicollinearity red flag (VOL≈WT at 0.999 corr, HP≈SP at 0.974) before modeling; Evaluation step traces that warning through to an actual payoff — `SP` and `WT`'s coefficients **flip sign** between their solo correlation with MPG and their multivariate coefficient, directly demonstrating `02-Linear Regression/theory.md` Section 8's multicollinearity assumption, with an explicit caveat about what's safe to interpret vs. not. RMSE 5.65 vs. a 10.16 mean-baseline, R²=0.675.
- **`03-Logistic Regression/scripting.ipynb`** — trains Logistic Regression on `assets/claim.csv` (1340 rows, insurance bodily-injury claims) to predict `ATTORNEY` (did the claimant retain an attorney), confirmed with Varun: binary, roughly balanced (685/655), a realistic business question. Data Preparation drops the `CASENUM` ID column and rows with missing values (1340→1096, tradeoff stated rather than silently imputed) with a stratified split. Evaluation compares against a majority-class baseline (0.673 vs 0.527 accuracy) with confusion matrix, precision/recall, ROC-AUC (0.745), then interprets coefficients in plain English with an association-vs-causation caveat.

Needed `scikit-learn`, `matplotlib`, `seaborn` installed via pip (only pandas/numpy were present before). Every cell in both notebooks was actually executed end-to-end (from each chapter folder, since both use a relative `../assets/...` path) to verify it runs and that every markdown commentary number matches real output before being written to the notebook — including the saved `.pkl` model files themselves being real, loadable artifacts, not just described.
